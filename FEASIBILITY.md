# Что из демо мы реально сможем реализовать

Проверка от 19.08.2026. Вопрос простой: для каждого блока новых экранов —
можно ли его довести до настоящей работы на данных банка, или это красивая
картинка, которую придётся убирать на пилоте.

Проверялось по фактической схеме БД (`\d` в postgres), существующим API и
тому, что уже умеет бэкенд. Не по памяти.

## Итог одной строкой

Из показанного **реализуемо почти всё**. Данные для метрик уже лежат в базе,
модель и поиск уже работают. Убрано то, для чего нет ни данных, ни
интеграции — список в конце.

## 1. Метрики: реализуемо полностью

Всё считается запросами к существующим таблицам, ничего добавлять в схему
не нужно.

| Показатель на экране | Откуда возьмём | Готовность |
|---|---|---|
| Обращений за период | `conversations.created_at` | считается уже сейчас |
| Решено силами AI / эскалаций | наличие строки в `escalations` | считается уже сейчас (`bot_share`) |
| Среднее время ответа, p95 | `messages.latency_ms` | считается уже сейчас |
| CSAT | `feedback.score` (1–5) | считается уже сейчас |
| Ответы со ссылкой на источник | `messages.chunks_used` не пуст | считается уже сейчас |
| Сэкономленные часы | решённые × среднее время диалога | `hours_saved` уже в `/api/analytics` |
| Время решения оператором | `escalations.resolved_at − created_at` | поля есть, запрос не написан |
| Первый ответ человека | `escalations.taken_at − created_at` | поля есть, запрос не написан |
| Нагрузка на оператора | группировка по `escalations.taken_by` | поля есть, запрос не написан |
| Повторные обращения | `contacts` → число `conversations` | поля есть, запрос не написан |
| Изменение к прошлому периоду | те же запросы с другим окном дат | тривиально |

**Вывод:** новых полей в схеме не требуется. Работа — написать SQL и отдать
в `/api/executive`.

## 2. Темы обращений: реализуемо, но это работа

На экране показаны «Переводы и комиссии», «Карты и блокировки» и т.д. Поля
`topic` в схеме нет. Два пути, оба рабочие:

1. **По процитированным документам.** `messages.chunks_used` → `chunks` →
   `documents.title`. Диалог, где цитировалась статья о переводах, относится
   к теме переводов. Дёшево, работает сразу, покрывает те диалоги, где ответ
   нашёлся.
2. **Кластеризация вопросов.** Для диалогов без ответа (`no_answer`) первый
   способ не работает — там как раз и живут новые проблемы. Эмбеддинги
   вопросов мы уже считаем (bge-m3), нужна кластеризация и название кластера
   моделью.

**Вывод:** реализуемо. Первый способ — дни, второй — недели.

## 3. Находки и разбор причины: реализуемо с оговоркой

- **Аномалия «+37% по теме»** — сравнение долей тем между периодами.
  Чистая арифметика поверх п.2.
- **Новая проблема** — кластер, которого не было в прошлых периодах. Тоже
  поверх п.2.
- **Причина («тариф сменился, статья не обновлялась»)** — связывание всплеска
  с `documents.indexed_at`. **Поле в схеме есть**, дата последнего обновления
  статьи достаётся честно. Формулировку пишет модель по сводке.

**Оговорка:** причинно-следственная связь остаётся гипотезой модели. Так и
надо подавать — «вероятная причина», с основаниями, которые видно. Ровно так
экран и устроен.

## 4. Панель оператора: реализуемо

- **Сводка, намерение, настроение** — сейчас это правила на фронте
  (`components/OperatorAI.tsx`), намеренно: оператору нужен ответ мгновенно,
  а генерация занимает до 7,3 с (p95 стенда). Настоящая версия — вызов
  модели в фоне при эскалации, результат в новое поле `conversations`.
  Модель уже развёрнута, промпт — обычная задача.
- **Заготовка ответа** — уже работает: берётся из `hint`, который бэкенд
  и так возвращает.
- **Перевести / сократить** — SoroLLM это умеет, ru↔tj уже в проде.

**Вывод:** реализуемо. Потребуется одно поле в схеме и фоновая задача.

## Что убрано как нереализуемое

**1. «Создать задачу»** (было в рекомендациях и в демо).
Таск-трекера нет, таблицы задач в схеме нет, интеграции с системами банка
нет. Кнопка выглядела работающей, а задача уходила бы в никуда. Заменено на
**«Отправить сводку руководителю»** — этот путь реален: Telegram-бот и
`OWNER_TELEGRAM_IDS` уже используются для отчётов в `core/reports.py`.

**2. «Поделиться» отчётом.**
Почтовой рассылки и публичных ссылок на отчёт в системе нет. Убрано с обоих
экранов. Выгрузки PDF/XLSX оставлены — они реализуемы.

**3. «Аптайм 30 дн — 99,94%»** в подвале бокового меню.
Число пришло из эталонного прототипа и было просто нарисовано: мониторинга
доступности в системе нет, считать аптайм не из чего. Первый же вопрос — «за
какой период и чем меряли» — оставался без ответа. Убрано.

**4. WhatsApp в списке каналов** (подпись к числу обращений).
Канал не подключён: в `.env` вместо токена и номера стоит `ЗАПРОСИТЬ`.
Приписывать ему обращения — обещать работающую интеграцию. Осталось
«Telegram и веб-виджет» — то, что работает.

**5. Семь типов отчётов с одинаковым содержимым.**
Это была самая заметная подделка: выбираешь «Риски и эскалации» — получаешь
недельный отчёт целиком. Теперь каждый тип собирается из своего набора
разделов (`reportFor` в `lib/intel.ts`): ежедневной сводке не нужен разбор
причин, отчёту по рискам — эффект для бизнеса. Так это и будет работать на
бэкенде: одни срезы данных под разные вопросы.

**7. Метрика «Экономия на операциях — $18 400».**
Переводила сэкономленные часы в деньги по ставке $6,25/час, которую мы
придумали сами. Число выглядело точным фактом, хотя целиком держалось на
нашем допущении о стоимости часа оператора — а её знает только банк.
Убрана с дашборда, из блока «Эффект для бизнеса», из недельного отчёта и из
финального шага демо. **Часы оставлены**: они измеримы, считаются из
диалогов и не требуют внешних допущений — банк переведёт их в деньги сам по
своей ставке, и такой расчёт будет его собственным.

**8. «Настроение клиента»** в панели оператора и в демо.
Определялось списком слов и на живых диалогах ошибалось заметно: «почему с
меня списали комиссию» — обычный вопрос, а по слову «почему» помечался как
«обеспокоен». На смеси русского с таджикским тем более. Оператор, увидевший
неверную пометку, начинает разговор не с той интонации — это хуже, чем
отсутствие подсказки. Вернуть можно только вызовом модели и только после
проверки на реальных диалогах банка.

**6. Кнопки-пустышки внутри Killer Demo** («Вставить ответ», «Сократить»,
«Перевести», «Экспорт»). Внутри презентации это витрина рабочего места, а не
сам инбокс — кликабельная кнопка, которая ничего не делает, читается как
поломка. Сделаны неактивными. Рабочие версии живут на экранах 06 и 09.
