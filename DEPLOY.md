# Прод-деплой: сервер, HTTPS, бэкапы

Что нужно от сервера: 4 ядра, 16 ГБ памяти, 60 ГБ диска, Docker 24+,
открытые 80 и 443. Меньше памяти — TEI не прогреется: замер на машине с
15,4 ГБ лежит в комментарии к `docker-compose.override.yml`.

## 1. Первый запуск

```bash
git clone <репозиторий> && cd soro-business
cp .env.example .env          # секреты — у тимлида
export SORO_DOMAIN=soro.example.tj      # домен уже смотрит A-записью на сервер
cd console && npm ci && npm run build && cd ..   # консоль соберётся в console/dist

docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
docker compose exec backend alembic upgrade head
```

`docker-compose.override.yml` на сервере **не нужен** — он локальный, для
машины разработчика. Compose подхватывает его автоматически, поэтому на
проде его либо удаляют, либо переименовывают.

Проверка:

```bash
curl https://$SORO_DOMAIN/health          # {"status":"ok", ...}
curl https://$SORO_DOMAIN/console/        # консоль
```

## 2. Что делает Caddy

Сертификат Let's Encrypt получает и продлевает сам — ни certbot, ни крона.
Конфиг в `deploy/Caddyfile`, три вещи в нём не косметические:

* **`flush_interval -1` для `/widget/stream` и `/api/playground/stream`.**
  Без него ответ бота приходит одним куском в конце: буферизация ломает
  SSE, и «печатается по мере генерации» превращается в шесть секунд
  молчания.
* **`X-Frame-Options` НЕ ставится.** Виджет живёт в iframe на сайте банка;
  запрет фреймов сломал бы ровно то, что мы продаём.
* **Домен из окружения.** Нет домена — `SORO_DOMAIN=:80`, Caddy работает
  без TLS: сертификат на IP-адрес не выдают.

Порты бэкенда и базы наружу не публикуются: до них ходит только Caddy
внутри сети compose. На стенде разработки 5432 и 8000 открыты — там это
нормально, здесь недопустимо.

## 3. Бэкапы

Контейнер `backup` снимает `pg_dump -Fc` раз в сутки в volume `backups`,
хранит 14 дней (`BACKUP_KEEP_DAYS`). Формат custom, а не SQL: он сжат,
восстанавливается выборочно и переживает pgvector — обычный дамп требует,
чтобы расширение уже стояло.

```bash
# снять снимок прямо сейчас
docker compose -f docker-compose.yml -f docker-compose.prod.yml \
    exec backup /bin/sh /backup.sh

# посмотреть, что есть
docker compose ... exec backup ls -lh /backups

# восстановить (ПЕРЕЗАПИШЕТ данные)
docker compose ... exec -T db pg_restore -U soro -d soro --clean --if-exists \
    < soro-2026-08-13-0300.dump
```

**Проверять восстановление, а не наличие файлов.** Бэкап, который никогда
не разворачивали, — это не бэкап. Раз в месяц: поднять пустую базу,
залить в неё последний дамп, открыть консоль и убедиться, что документы и
диалоги на месте.

Дампы лежат в docker volume, то есть на том же диске, что и база. Для
пилота этого мало: настроить выгрузку в S3 или на второй сервер — задача,
которую надо закрыть до боевого запуска, и она не решается этим файлом.

## 4. Нагрузочный прогон

```bash
docker compose ... exec backend python scripts/loadtest.py --users 25
```

Гоняет полный путь клиента через виджет: POST, ожидание ответа в
SSE-потоке, разбор `final`. Замер на демо-стенде (4 ядра, CPU, заглушка
модели):

| одновременных клиентов | медиана | 95-й перцентиль |
|---|---|---|
| 1 | 5,2 с | — |
| 8 | 10,5 с | 10,5 с |
| 25 | 16,0 с | 22,2 с |

Сбоев ни в одном заходе не было — все клиенты дождались ответа. Но время
растёт линейно, и причина известна: **эмбеддинги считаются на CPU по
3–4 секунды и по очереди**, TEI обрабатывает батчи последовательно. Это
дно, ниже которого не опуститься никакой параллельностью на этом железе.

Что с этим делать перед пилотом — по убыванию эффекта:

1. GPU для TEI: тот же образ с тегом `cuda`, поиск ускоряется примерно в
   двадцать раз, и всё остальное перестаёт быть узким местом;
2. кеш эмбеддингов частых вопросов: на демо половина вопросов повторяется;
3. второй воркер uvicorn — уже сделано (`--workers 2`), но упирается всё
   равно в TEI.

Норматив «ответ < 6 секунд» из раздела 3 относится к одиночному вопросу на
незагруженном стенде и этими цифрами не отменяется — но обещать его при
двадцати пяти одновременных клиентах на CPU нельзя.

      снимок;
