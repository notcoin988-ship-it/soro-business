# Как подготовить демо для нового банка

Одна страница, по шагам. Всё, что дольше пяти минут, помечено — планируйте
подготовку **накануне**, а не за полчаса до встречи.

## 1. Стенд (10 минут)

```bash
cp .env.example .env          # секреты взять у тимлида
docker compose up -d          # db, redis, embeddings, backend, worker
docker compose ps             # все пять — running
```

Проверка, что живо:

```bash
curl localhost:8000/health                       # {"status":"ok", ...}
curl -X POST localhost:8080/embed -H 'Content-Type: application/json' \
     -d '{"inputs":"салом"}' | head -c 40        # массив из 1024 чисел
```

`embeddings` при первом запуске качает 2 ГБ весов — это те самые «дольше
пяти минут». На второй раз веса лежат в volume `teidata`.

## 2. База знаний банка (30–60 минут, **накануне**)

Экран 02 «База знаний» → загрузить 2–3 PDF с тарифами и добавить сайт
банка одной ссылкой. Обход сайта — сотня-полторы страниц, это десятки
минут; PDF на 40 страниц — около трёх минут на CPU.

Дальше **обязательно**: прогнать `scripts/eval_rag.py` и посмотреть
recall@3. Если ниже 85% — на демо будут эскалации вместо ответов, и
чинить это надо документами, а не порогом.

```bash
docker compose exec backend python scripts/eval_rag.py
```

**Главная ловушка.** Вопросы для демо берите из документов банка, а не из
головы. В прототипе фигурирует вклад «Ояндасоз», которого у Эсхаты не
существует, — вопрос про него на встрече даст эскалацию, и объяснять
придётся вам. Проверьте каждый демо-вопрос заранее на экране 03: справа
должно быть три фрагмента, лучший — выше порога 0,60.

## 3. Каналы (15 минут)

**Telegram.** Бот у @BotFather, токен в `.env`. Затем публичный адрес:

```bash
ngrok http 8000                                  # адрес → PUBLIC_BASE_URL
docker compose up -d backend                     # перечитать .env
docker compose exec backend python scripts/tg_webhook.py --set
docker compose exec backend python scripts/tg_webhook.py --info
```

ngrok при каждом перезапуске выдаёт **новый** адрес, и вебхук молча
замолкает — бот просто перестаёт отвечать. Проверяйте `--info` перед
каждой встречей; «в очереди 0» и пустая строка ошибки — норма.

**Виджет.** Ничего настраивать не нужно: `loader.js` отдаёт сам бэкенд.
Сниппет для сайта банка показан на экране 05 уже с правильным адресом —
копируется как есть. Две страницы для проверки:

* `{PUBLIC_BASE_URL}/widget/site` — **это показывают на встрече**: обычная
  светлая страница банка с виджетом в углу, «вот так это будет у вас».
  Кнопка «Показать на сайте» на экране 05 ведёт сюда;
* `{PUBLIC_BASE_URL}/widget/demo` — технический полигон с намеренно
  враждебными стилями: на нём проверяют, что чужой CSS не ломает виджет.

У бесплатного ngrok браузер сначала получает страницу-предупреждение — и
в iframe виджета тоже. Откройте демо-страницу один раз, нажмите
«Visit Site», дальше кука действует на весь домен.

**WhatsApp** пока не подключён.

## 4. Прогон приёмки (15 минут, **три раза подряд**)

```bash
docker compose exec backend python scripts/acceptance.py
```

Восемь шагов раздела 6.1 с фактическими числами по каждому. Шаги 4 (QR с
телефона) и 6 (WhatsApp) закрываются руками — скрипт печатает, что именно
сделать. Код возврата 1 означает срыв прогона, так что три прогона можно
запустить циклом.

## 5. За полчаса до встречи

- [ ] `docker compose ps` — пять сервисов running;
- [ ] `scripts/tg_webhook.py --info` — вебхук на текущем адресе ngrok;
- [ ] экран 01 — контур безопасности включён целиком;
- [ ] экран 03 — задать демо-вопрос, увидеть три фрагмента и ответ;
- [ ] экран 06 — очередь оператора не забита мусором прошлых прогонов;
- [ ] экран 07 — цифры за 7 дней не пустые;
- [ ] телефон с Telegram заряжен и подключён к интернету (не к вашему
      ноутбуку по USB).

## Что говорить, когда что-то не работает

- **Бот молчит в Telegram** — вебхук на мёртвом адресе ngrok. Чинится за
  минуту, см. шаг 3.
- **Ответ «этой информации нет в документах»** — так и задумано: бот не
  выдумывает. Покажите на экране 03, что лучший фрагмент ниже порога, и
  это честный отказ, а не поломка.
- **Ответ идёт дольше шести секунд** — на CPU поиск занимает 3–4 секунды
  из них. На сервере с GPU это в разы быстрее; цифра на экране 07
  («медиана ответа») — ваш аргумент, она считается по фактическим
  ответам, а не по обещаниям.
